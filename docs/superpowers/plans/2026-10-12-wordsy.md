# Wordsy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Wordsy, a personal home-screen web app that teaches up to 3 curious words a day using flip-card recall, and keeps every word in a day-by-day archive.

**Architecture:** A static site with no framework and no build step. All the rules live in a pure, unit-tested module (`js/engine.js`). `js/store.js` loads and saves state to localStorage. `js/app.js` connects browser events to the engine and renders the DOM. A service worker makes the app work offline.

**Tech Stack:** HTML, CSS, JavaScript (ES modules); Node ≥ 20 `node --test` for tests; self-hosted woff2 fonts; GitHub Pages hosting.

**Spec:** `docs/superpowers/specs/2026-10-12-wordsy-design.md` (mockup: `docs/mockups/layouts.html`)

## Global Constraints

- No runtime dependencies and no build step. The only dev tooling is `node --test`.
- A visit starts on the first foreground of the local day, or when the app returns after **≥ 60 minutes** away (`VISIT_GAP_MS = 3_600_000`).
- At most **3** new words per day (`WORDS_PER_DAY = 3`). The day boundary is local midnight.
- Low-stock notice when unseen words are **< 90** (`LOW_STOCK_WORDS = 90`). Copy: `About N days of words left.` where N = ceil(left / 3).
- Out-of-words copy: `You've seen every word.`
- Quiz directions are the string literals `"word-to-meaning"` and `"meaning-to-word"`.
- localStorage key: `wordsy:v1`. State `version: 1`.
- Typefaces: Newsreader (400, 400 italic, 600), IBM Plex Sans (400, 500, 600), IBM Plex Mono (400). Latin subset woff2, self-hosted in `fonts/`.
- The theme follows `prefers-color-scheme` only, with no toggle. Day: off-white `#fbfbf9` page, white `#ffffff` cards, ink-blue accent `#2443a8`. Night: navy `#131726` page, `#1c2134` cards, lilac accent `#c4b3ff`. Take the remaining tokens from `.skin-a` / `.skin-c` in the mockup.
- Headwords shrink to fit the card, never below 14px.
- Word entries are append-only: never reorder, rename or remove an `id`.

## Review Focus

1. **The app is killed without `pagehide` firing** (common for iOS home-screen apps). The gap must be measured from the last time the app was *seen*, so `app.js` calls `onHidden` every 60s while visible as a heartbeat. Test: `heartbeat keeps a reopen within 60 min in the same visit` (Task 2).
2. **Reopening across midnight within 60 minutes** (closed 23:50, reopened 00:10) must start Day N+1 visit 1, not continue yesterday. Test: `midnight rollover counts as a new visit even inside the gap` (Task 2).
3. **The clock moves backwards, or `lastHiddenAt` is in the future**: no duplicate day, no new visit, no crash. Test: `clock going backwards keeps today and does not add a visit` (Task 2).
4. **Words run out partway through a day** (visit 2 with no unseen words left): the quiz still runs, no new word appears, and the out-of-words message shows. Test: `visit 2 with no words left quizzes and shows outOfWords` (Task 3).
5. **Storage holds corrupt JSON or an old shape**: the app starts fresh and doesn't throw. Test: `load returns fresh state on corrupt JSON` (Task 5).

## Shared types (defined in Task 1, used everywhere)

```js
// Word: { id, word, ipa, pos, definition, examples: [string, string, string] }
// State:
{
  version: 1,
  nextIndex: 0,
  lastHiddenAt: null,          // ms, last time the app was seen (hidden or heartbeat)
  today: Today | null,
  history: [ { date, dayNumber, wordIds: string[] } ],   // oldest first
  grades: { [id]: [ { at, direction, knew } ] }
}
// Today:
{
  date: "YYYY-MM-DD", dayNumber, visits: 0,
  newWordIds: [], relearnIds: [], quizCounts: {},
  pendingNewWord: false,       // a new word is waiting behind the current quiz
  screen: Screen
}
// Screen (what the Today view shows):
//   { type: "word", id }
//   { type: "quiz", id, direction, flipped: false, graded: null | true | false }
//   { type: "empty" }          // nothing to show (no words yet or the list is exhausted)
```

All engine functions are pure: they return a new state and never mutate their input. Tests assert this by deep-freezing inputs (`deepFreeze` helper in `tests/helpers.js`).

### Task 2: Day rollover and visit detection

**Files:**
- Modify: `js/engine.js`
- Test: `tests/engine.visits.test.js`

**Interfaces:**
- Consumes: Task 1 exports.
- Produces: `onHidden(state, now): State` (sets `lastHiddenAt = now`) and `onForeground(state, words, now): State`. Task 3 fills in what a new visit shows. In this task `onForeground` only performs the rollover and the `visits` increment, and calls an internal `beginVisit(state, words, now)` stub that returns the state unchanged.

Rules for `onForeground`:
1. `d = localDate(now)`. If `today` is null, or `d > today.date` (string compare): push the old `today` to `history` as `{date, dayNumber, wordIds: newWordIds}` **only if** it has words. Create a fresh `today` with `dayNumber = (last history dayNumber or old today.dayNumber or 0) + 1`, `screen: {type:"empty"}`, and treat this as a new visit.
2. Otherwise (`d <= today.date`, so the same day, or a clock that went back) it's a new visit only if `lastHiddenAt !== null && now - lastHiddenAt >= VISIT_GAP_MS`.
3. On a new visit: `visits += 1`, then `beginVisit`. Always set `lastHiddenAt = now`, so the next gap measures from this foreground.

- [ ] **Step 1: Write failing tests:**
  - `first ever foreground creates Day 1 visit 1`
  - `reopen after 59 min is the same visit` (visits stays 1)
  - `reopen after exactly 60 min is a new visit` (visits 2)
  - `heartbeat keeps a reopen within 60 min in the same visit`: foreground t0 → `onHidden` at t0+50min → foreground at t0+100min → visits 1
  - `midnight rollover counts as a new visit even inside the gap`: 23:50 → hidden 23:51 → foreground 00:10 → dayNumber 2, visits 1, previous day in history only if it had words
  - `day with no words is not archived but still advances dayNumber? ` → **No.** Assert that a zero-word day is not pushed and that `dayNumber` = previous day's number + 1 (days are counted from `today`, not history)
  - `clock going backwards keeps today and does not add a visit`: today.date 2026-10-12, now is 2026-10-11 and `lastHiddenAt` is in the future → same `today`, visits unchanged, no throw
  - `inputs are not mutated` (deepFreeze)
- [ ] **Step 2:** `npm test`. Expected: the new tests FAIL.
- [ ] **Step 3:** Implement `onHidden` and `onForeground` per the rules above.
- [ ] **Step 4:** `npm test`. Expected: PASS.
- [ ] **Step 5:** Commit `feat: day rollover and 60-minute visit detection`.

> Note on the "day with no words" test: a fresh day always gets `dayNumber = previousToday.dayNumber + 1`. A day only exists once the app was opened on it, which matches the spec ("days with no visits don't appear"). A day that was opened but showed no words (because the list was exhausted) is numbered but not archived.

### Task 3: What a visit shows, quizzes, grading, relearn, stock

**Files:**
- Modify: `js/engine.js`
- Test: `tests/engine.today.test.js`

**Interfaces:**
- Consumes: Task 2's `onForeground` / `beginVisit`.
- Produces:
  - `pickQuiz(today): {id, direction} | null`
  - `flipQuiz(state): State` (sets `screen.flipped = true`)
  - `gradeQuiz(state, knew: boolean, now): State`
  - `advance(state, words): State` (the button after grading)
  - `toggleRelearn(state, id): State`
  - `stock(state, words): {left: number, low: boolean, daysLeft: number, out: boolean}`
  - `isRelearn(state, id): boolean`

Rules:
- `beginVisit`, by visit number. It's internal; replace the Task 2 stub.
  - Visit 1: if a word is available, reveal it (append `words[nextIndex].id` to `newWordIds`, `nextIndex += 1`, screen `{type:"word", id}`). Otherwise screen `empty`.
  - Visits 2–3: `pendingNewWord = nextIndex < words.length`. Then start a quiz (`pickQuiz`). If the pool is empty, reveal the pending word directly; if there's nothing at all, `empty`.
  - Visit 4+: start a quiz, or `empty` if the pool is empty.
- `pickQuiz`: pool = `newWordIds` followed by `relearnIds` (in insertion order). Choose the lowest `quizCounts[id] ?? 0`; break ties by the **latest** position in the pool. Direction: `quizCounts[id]` even → `"word-to-meaning"`, odd → `"meaning-to-word"`.
- `gradeQuiz`: requires `screen.type === "quiz"`. Sets `screen.graded = knew`, increments `quizCounts[id]`, and appends `{at: now, direction, knew}` to `grades[id]`.
- `advance`: if `pendingNewWord`, reveal the next word and clear the flag. Otherwise start another quiz.
- `toggleRelearn`: add `id` to `relearnIds`, or remove it if already there. Ignore ids already in `newWordIds`.
- `stock`: `left = words.length - nextIndex`, `low = left > 0 && left < LOW_STOCK_WORDS`, `daysLeft = Math.ceil(left / WORDS_PER_DAY)`, `out = left === 0`.

- [ ] **Step 1: Write failing tests** (use a 5-word fixture `W`):
  - `visit 1 reveals word 0 and advances nextIndex`
  - `visit 2 quizzes word 0 word-to-meaning with pendingNewWord true`
  - `grading then advance reveals word 1`
  - `visit 3 quizzes the least-quizzed word, ties to most recent` (after visit 2's quiz of w0: visit 3 picks w1)
  - `visit 4 quizzes only, never reveals` (`nextIndex` stays 3 after visit 4, then advance → another quiz)
  - `direction alternates per word`: second quiz of w0 is `"meaning-to-word"`
  - `grade is recorded with timestamp and direction`
  - `relearn adds an archived word to the pool and toggles off`
  - `relearn resets on the next day`
  - `visit 2 with no words left quizzes and shows outOfWords`: 1-word fixture, so visit 2 → quiz w0, `pendingNewWord` false, `stock().out === true`
  - `stock low threshold`: 89 left → low true, daysLeft 30; 90 left → low false
  - `inputs are not mutated`
- [ ] **Step 2:** `npm test`. Expected: the new tests FAIL.
- [ ] **Step 3:** Implement per the rules above.
- [ ] **Step 4:** `npm test`. Expected: PASS.
- [ ] **Step 5:** Commit `feat: visit content, flip-card quizzes, grading and relearn`.
